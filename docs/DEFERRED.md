# Отложенные задачи — реестр

Единая точка учёта работ, которые осознанно отложены. Каждая запись
содержит контекст и критерий закрытия. Создан 2026-09-08 после
инвентаризации планов.

## 1. Безопасность JWT — хвост ревью PR #27

Источник: Claude-ревью миграции JWT storage, вердикт REQUEST_CHANGES.
Критичные пункты закрыты в PR #27; нижеперечисленное отложено
сознательно — это дизайн-изменения, а не баги.

### 1.1. sid-claim: мгновенная ревокация access-токенов
- Сейчас access-токен жив до конца TTL, даже если его сессия ревоцирована
  через logout / revoke / смену пароля — окно до 10 минут.
- Критерий: access-токен несёт sid = token_sessions.id;
  deps проверяет revoked_at IS NULL; ротация переносит sid.

### 1.2. Refresh-reuse: grace window + family scope
- Сейчас повтор presentation отозванного refresh-токена ревоцирует ВСЕ
  сессии пользователя; потерянный ответ при ротации выкидывает все
  устройства. Нет family_id/parent_id у token_sessions.
- Критерий: rotated_at + replacement_id на строке; повтор в пределах
  ~30 c возвращает тот же successor; ревокация ограничена семейством.
- Диспозиция Codex-ревью 2026-09-08: ветка проигранной гонки claim
  (rowcount=0) намеренно возвращает 401 БЕЗ ревокации семьи. Атакующий,
  проигравший гонку, не получает ничего — ротированный successor уходит
  победителю, украденный старый токен мёртв; а настоящий replay
  отозванного токена вне гонки попадает в reuse-ветку и ревоцирует
  семью. Ревокация на каждый проигрыш ломала бы легитимные мульти-таб
  сессии. Grace window из этого пункта — корректное решение конфликта.

### 1.3. Тест-сьют в дефолтном M4-режиме
- conftest ставит AUTH_BODY_TOKENS_ENABLED=true: 590+ тестов гоняют
  rollback-конфиг; дефолт покрыт только test_jwt_m4.py.
- Критерий: дефолт конфорта = M4; dual-mode помечен явной фикстурой.

### 1.4. Pruning token_sessions
- Строки не удаляются; при ротации каждые ~10 минут это десятки строк
  на пользователя в день.
- Критерий: celery-beat задача или opportunistic-чистка в
  create_token_session: expires_at в прошлом OR revoked_at старше 7 дней.

### 1.5. __Host- префиксы cookie
- AUTH_COOKIE_NAME и refresh cookie без префикса; префиксы дают браузерные
  гарантии, но меняют имена cookie и инвалидируют текущие сессии.
- Критерий: cookie переименованы с __Host-, задокументирован миграционный
  шаг деплоя.
